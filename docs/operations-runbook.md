# التشغيل والمراقبة والنشر والرجوع

## بيئة الاختبار

`npm run dev` يبني الواجهة ويشغّل خمس جلسات على 127.0.0.1:4173–4177 وقاعدة
PGlite في الذاكرة. الرمز التجريبي `12345678` يُنشأ في تلك القاعدة فقط. يستبدل
الخادم عنوان API عند إرسال JavaScript بالعنوان المحلي `/test-api`. لا يرسل
اختبار الحمل طلبات شبكة، واختبارات المتصفح تمنع الاتصالات الخارجية.

يمكن تحديد `PORT` و`TEST_DIST` و`TEST_EDGE_SOURCE` لتثبيت نسخة مستقلة للمقارنة.
أدوات الاختبار ليست ضمن حزمة النشر. بيانات الاختبار لا تدخل قاعدة الإنتاج.

## المراقبة

يصدر الخادم أحداث JSON من نوع `mafia.request`: الأخطاء، الطلبات التي تتجاوز
ثانية، وعينة من كل عشرين طلبًا سليمًا. `MAFIA_LOG_ALL=true` مخصص للتشخيص المؤقت؛
تفعيل كل الطلبات دائمًا قد يتجاوز حدود السجلات. لا تُسجّل بيانات الأدوار أو
الأسماء أو رموز الجلسات أو نص الاستثناء الخام.

شغّل `npm run monitor` مع `MAFIA_MONITOR_URL` لعنوان API المحدد. إذا ضُبط
`MAFIA_MONITOR_HOST_TOKEN` من جلسة مضيف مصرح لها، تشمل المراقبة المراحل النشطة؛
بدونه تفحص صحة الخدمة فقط. لا تضع الرمز في سطر الأوامر أو ملفات المستودع.
`--once` يعطي عينة للتحقق، والوضع المستمر يأخذ عينة كل 30 ثانية.

تحتاج الحالة ثلاث عينات متتالية للتنبيه، ويُكبت تكرار التنبيه 15 دقيقة ويُسجّل
التعافي. حد التأخر ثانية، وحد بقاء المرحلة 15 دقيقة؛ عدّل `MAFIA_STALE_MINUTES`
وفق إدارة المباراة. التوقف المتعمد والردهة والنهاية مستثناة. تنبيه المرحلة
يطلب مراجعة المضيف ولا يغيّر المرحلة تلقائيًا. العدادات الخاصة بالنسخة العاملة
من المعالج ليست إحصاءات عالمية دائمة.

راجع السجلات عبر [Supabase Logs](https://supabase.com/docs/guides/functions/logging).
معرّف `X-Request-Id` يربط بلاغ المستخدم بالحدث دون طلب رمزه الخاص.

## بوابة الإصدار

1. نفّذ `npm run preflight`: بناء متطابق مع المصادر، اختبارات السلوك والخصوصية
   والتزامن، فحوص الكاش، واختبار عدم تراجع LCP اعتمادًا على القياسات المحفوظة.
2. نفّذ اختبارات المتصفح على الحزمة نفسها، ومنها `tests/final-journeys-browser.mjs`.
3. شغّل `node scripts/deploy-performance.mjs prepare` لتجميد الملفات مع SHA-256.
   لا تُضمّن `src` أو الاختبارات أو السجلات أو مفاتيح البيئة في النشر.
4. احتفظ بمصدر Edge السابق ومعرّف نشر Vercel السابق في مجلد الإصدار. تحقق من
   وجود RPC المطلوبة وصلاحيات service_role قبل تحديث Edge. هذا الإصدار لا
   يضيف migrations؛ لا تشغّل bootstrap على الإنتاج.
5. انشر `supabase/functions/mafia-room/index.ts` ثم حزمة الواجهة المجمدة؛ راقب
   health وسجلات الأخطاء وتطابق ملفات الموقع مع manifest بعد أن تصبح READY.

## الرجوع

أعد نشر ملفات Edge السابقة المحفوظة في `artifacts/assurance/rollback-edge-v46.ts`
بنفس اسم الوظيفة وإعداد المصادقة السابق. في Vercel أعد توجيه الإنتاج إلى
معرّف الإصدار المحفوظ في `artifacts/assurance/previous-deployment.json` باستخدام
أداة rollback الرسمية. لا تتراجع عن بيانات المباراة أو قاعدة البيانات.

اختبار `npm run test:operations` يشغّل مصدر الإصدار السابق على قاعدة اختبار،
ويبدأ مباراة، ويبدّل إلى المصدر الجديد أثناء كشف الدور، ثم يرجع للمصدر السابق
في النهار ويكمل التصويت. يقارن هوية المباراة والأدوار والجلسات، ويحقن خطأ قاعدة
متعمدًا ليثبت كشفه دون تسريب محتواه، ويثبت كشف التوقف وكبت التنبيه المتكرر.
هذه تجربة تبديل معالج محلية؛ ليست ادعاء تجربة rollback على إنتاج مستخدمين.

نجح أيضًا `tests/deployment-browser.mjs`: تبديل ملفات الواجهة ومعالج الخادم
خلف HTTP محلي أثناء صفحة لاعب نشطة، ثم إعادة تحميل الصفحة والرجوع، مع بقاء
المباراة والجلسة والدور. النتائج في `artifacts/assurance/deployment-browser.json`.

بتاريخ 2026-09-13 نُشرت Edge 47 وحزمة الواجهة `8e12ba28b3fc0437`، وتحقق تطابق
59 ملفًا على نطاق الإنتاج ونجح health برمز 200. فُعّلت متابعة في هذه المهمة
كل خمس دقائق للصحة وتأخر الطلبات ومراحل المباريات، بثلاث عينات للتأكيد
وكبت التكرار 15 دقيقة. تعتمد المتابعة على إتاحة تشغيل المهمة واتصالاتها؛
ليست خدمة مراقبة مستقلة عن التطبيق. لا تستخدم المتابعة رموز جلسات اللاعبين.

النتائج الخام وقيود السعة في `artifacts/assurance`. أعد القياس بعد تغيير الخادم
أو العتاد أو شكل الحمل؛ لا تحوّل نتائج اتصال PGlite المتسلسل إلى سعة Supabase.
